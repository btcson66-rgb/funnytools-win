# 流程圖怎麼畫才看得懂？方向、分支、斷路、循環與驗證清單

一張流程圖看起來整齊，不代表真的能用。

常見問題：

- 有箭頭卻不知道往哪走
- Decision沒有Yes/No語意
- 有一條路永遠走不到
- 某個節點沒有出口
- 走到最後又莫名回到開始

> **速答：流程圖怎麼畫才清楚？**  
> 先決定一個主要閱讀方向，再把每個Process寫成具體行動、每個Decision寫成可回答問題，確保每個分支有清楚下一步，並檢查所有路徑都能從起點走到合理終點。減少箭頭交叉與超長節點文字；完成後請一位沒有參與畫圖的人實際「走圖」，如果他需要口頭説明才能完成，流程圖就還沒有獨立傳達成功。

## 一、先寫流程，再打開繪圖工具

先用文字列出：

1. 收到申請
2. 檢查附件
3. 完整？
4. 否 → 補件
5. 是 → 審核
6. 結束

先把邏輯排對，再畫。

這比在空白畫布上邊想邊拉方塊有效。

## 二、一張圖只回答一個主要問題

例如：

> 「報帳怎麼完成？」

不要同一張又塞：
- 公司組織圖
- 權限矩陣
- KPI
- 系統架構

不同問題拆圖。

## 三、Process節點要用動詞

不清楚：

> 文件

更好：

> 上傳文件

不清楚：

> 審核

更好：

> 主管審核申請

節點是一個行動，不是章節標題。

## 四、Decision節點要能回答

不清楚：

> 金額

更好：

> 金額超過10,000元嗎？

出口自然就能是：

- 是
- 否

## 五、一致的主方向

建議主要方向只選一種：

- 上→下
- 左→右

例外分支可以側向，但不要讓主流程蛇行。

## 六、箭頭交叉代表什麼？

不一定代表邏輯錯，但通常表示：

> 版面可以再整理。

可以：
- 搬節點
- 分區
- 拆子流程
- 改主方向

讓視線少跳。

## 七、什麼叫斷路？

節點有進入箭頭：

> 卻沒有任何下一步。

如果它不是終點：

> 就是流程缺漏。

例如：
`主管退回`
然後沒有說：
- 回申請人？
- 結案？
- 再修改？

## 八、什麼叫孤立節點？

畫布上有一個方塊：

> 沒有任何箭頭連到它。

可能是：
- 忘記連線
- 已廢棄節點
- 只是備註

若是備註，不要偽裝成流程節點。

## 九、Decision只有一條出口合理嗎？

通常不合理。

如果問題是：

> 通過嗎？

卻只有「是」路徑，表示：
> 否的情況去哪？

至少要説明：
- 退回
- 結束
- 重試
- 例外處理

## 十、循環要有離開條件

例如：
不完整 → 補件 → 再檢查。

合理。

但應問：

> 補幾次都不完整怎麼辦？

真實流程可能還需要：
- 逾期
- 取消
- 人工介入

流程圖能幫你發現制度缺口。

## 十一、不要把政策文字全塞圖裡

節點：

> 「若申請人於收件後五個工作日內未補齊附件則依規定……」

太長。

圖中可寫：

> 5工作日內補件？

詳細政策放：
- 圖下註解
- SOP
- 連結

## 十二、節點命名要一致

若全部Process都用動詞：

- 收件
- 檢查
- 通知
- 歸檔

就不要突然有：

> 「附件狀態」。

一致的語法讓人更快掃描。

## 十三、顏色不要取代語意

例如：
- 綠色 = 通過
- 紅色 = 退回

如果沒有文字：

> 色覺差異使用者可能無法理解。

應同時使用：
- 文字
- 形狀
- 線條／位置

顏色只做輔助。

## 十四、流程圖完成後做Path Walk

從起點開始：

### Path A
每次Decision都走Yes。

### Path B
第一個Decision走No。

### Path C
不同組合。

確認：
- 每條路都存在
- 沒有死路
- 沒有錯接
- 沒有無限loop

## 十五、讓真正執行的人驗證

如果你畫的是：
> 報帳流程

最好讓：
- 申請人
- 主管
- 財務

其中至少一位看。

因為圖畫得合理，不代表現場真的這樣做。

## 十六、版本管理

FunnyTools現行流程圖沒有：
- autosave
- editable project
- version history

所以大幅調整前：

> 先匯出PNG備份。

如果流程需要長期維護，應使用可編輯專案格式的工具保存source。

## 十七、FunnyTools現行限制如何影響設計？

最多約20 nodes，而且：
- 直線arrow
- arrow無label
- no undo
- PNG 1000×620
- grid包含在輸出

因此一張圖應偏短。

如果要40～100個節點：

> 不是把字縮小，而是拆圖或換工具。

## 十八、分享前檢查表

- [ ] 有明確起點
- [ ] 有合理終點
- [ ] 主方向一致
- [ ] Process是行動
- [ ] Decision是問題
- [ ] 每個Decision分支都可理解
- [ ] 沒有孤立節點
- [ ] 沒有非預期斷路
- [ ] 循環有退出條件
- [ ] 文字在實際尺寸可讀
- [ ] 真正執行者看過
- [ ] 已保存備份

## 十九、FAQ

### 流程圖越詳細越好嗎？
不是。過細會失去概覽價值。

### 可以超過20個節點嗎？
FunnyTools現行工具約20節點上限，複雜流程應拆分或換專業工具。

### 為什麼要給別人測試？
因為作者容易自動補上自己腦中的背景資訊。

### 顏色可以表示Yes/No嗎？
可以輔助，但不能只靠顏色。

### FunnyTools會自動保存嗎？
不會，請匯出備份。
